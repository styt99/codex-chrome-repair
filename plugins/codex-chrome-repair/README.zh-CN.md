# Codex Chrome Repair

这个插件以通用英文发布名 `Codex Chrome Repair` 为 Windows 下的 Codex Desktop 打包 `chrome-xiufu` 技能。

请阅读[英文说明](README.md)或[完整技能说明](skills/chrome-xiufu/SKILL.md)。技能会完整定位 Chrome/Browser 控制链路，只应用精确的已知兼容补丁，动态跟随官方插件版本，并且必须完成真实 Chrome ACK 才能报告恢复完成。

`.codex-plugin/plugin.json` 中的版本是这个公开技能包自身的版本，与官方 `chrome@openai-bundled` 运行时版本相互独立，不会锁定官方插件版本。

## 已验证的修复前后数据

以下数据来自 Selenium 测试页上的真实 Chrome ACK。只有历史导航有修复前的实测基线，其余项目明确写为“修复前无数据”，不做估算。

| 操作 | 修复前 | 修复后 | 状态 | 数据来源 |
| --- | ---: | ---: | --- | --- |
| 冷启动导航 | 修复前无数据 | 1,149.9 ms | 通过 | Chrome ACK 复核 |
| 热导航 | 修复前无数据 | 1,061.6 ms | 通过 | Chrome ACK 复核 |
| URL / 标题 | 修复前无数据 | 3.6 / 3.2 ms | 通过 | Chrome ACK 复核 |
| 页面评估 / DOM 快照 / 截图 | 修复前无数据 | 119.8 / 103.0 / 117.3 ms | 通过 | Chrome ACK 复核 |
| 填充 / 按键 / 点击 | 修复前无数据 | 59.1 / 35.6 / 3,012.0 ms | 通过 | 表单 ACK 复核 |
| 滚动 / 位置确认 | 修复前无数据 | 请求 3,037.3 ms；等待 2.2 秒后确认 700 px | 通过 | Chrome ACK 复核 |
| `goBack` | 平均 10,048.7 ms | 71.6–104.2 ms，3/3 | 通过，约降低约 99.1% | 历史基线 + ACK 复核 |
| `goForward` | 平均 10,048.4 ms | 60.7–103.3 ms，3/3 | 通过，约降低约 99.0% | 历史基线 + ACK 复核 |
| 临时标签清理 | 修复前无数据 | 60.2 ms；受控标签 0 个 | 通过 | Chrome ACK 复核 |

冷启动和热导航因为连接和页面挂载发生在导航过程中，仍可能需要数秒，
但这是“成功但较慢”，不是插件故障。滚动命令返回成功后可能需要短暂落地，
因此 ACK 必须在 2.2 秒确认窗口后读取实际位置。历史操作是本次已测量的延迟修复，
每次都到达了正确 URL。
